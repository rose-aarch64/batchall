# Mobile Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Batchall comfortable to use one-handed on a phone: find a mini, check it, mark it painted, and look at or build a force, without sideways scrolling or tiny tap targets.

**Architecture:** The same single page in `web/` (plain HTML, CSS and JS, no framework, no second app). A "phone" mode switches on at a viewport width of 640px or less, by CSS media queries plus a small amount of JS. Wider screens keep today's layout. It works in both local mode and hosted mode, so nothing here touches `batchall/` or `hosted/`.

**Tech Stack:** Plain JavaScript and CSS. Tests drive headless Google Chrome through the DevTools protocol using only the standard library, and skip when Chrome is not installed.

**Spec:** none written. Rose asked for "a mobile interface" and chose to skip the questions ("Go"). The decisions below are the controller's calls, made after looking at screenshots of the current page at 390px wide on 2026-11-06.

## What is wrong at 390px today

From screenshots of the real page on a copy of the collection:
- Eight filter controls stack above the list, so the first screen shows no minis.
- The table is wider than the screen, with text inputs and selects in each row.
- Card buttons are about 28px tall. Most tap targets are under 44px.
- The bulk-edit bar wraps to five rows and covers about a third of the screen.
- The force tray and Saved forces sit far below the list.
- The top bar and tabs are small, and there is no safe-area handling for notched phones.

## Design decisions (all controller's calls; Rose can overrule any of them)

1. **Phone mode is a viewport width of 640px or less.** The mode is CSS first. JS reads it through `matchMedia("(max-width: 640px)")`.
2. **Cards only on a phone.** The Table and Density controls are hidden and the cards layout is used, because the table is a desktop tool. The saved desktop choice in `localStorage` (`batchall.view`) is never overwritten by phone use.
3. **Filters live in a bottom sheet.** The search box stays on top. A "Filters" button with a count of active filters opens a sheet holding every other filter plus Grouping and Sort. Filters still apply as you change them.
4. **Bottom tab bar** with three tabs: Collection, Forces, Import. The Forces tab shows the force tray and the Saved forces list. The top bar shrinks to the title and the account control.
5. **Bulk bar becomes a compact strip** with the selected count, "Mark painted", and an "Actions" button. The rest of the actions open in a sheet.
6. **Touch comfort:** every button, link and input is at least 44px tall in phone mode, inputs use a 16px font so iOS does not zoom, and the bars respect `env(safe-area-inset-*)`.
7. **Home-screen friendly:** `theme-color`, a web app manifest with `display: standalone`, and no offline mode and no service worker.
8. **Unchanged:** the detail panel's text sizes (tuned by hand earlier, so ask before changing them), the crimson-and-black look, fonts (system only), and everything at 641px and wider.

## Global Constraints

- No new dependencies and no build step. System fonts only.
- No inline `<script>` and no `style=` attributes in HTML (the hosted CSP forbids inline script and the existing tests check both pages).
- Wider than 640px, nothing changes. A test asserts the desktop controls are visible at 1280px.
- Phone mode must work with local mode (`python3 -m batchall serve`) and hosted mode (`/login.html`, `/api/auth/me`).
- The saved desktop view choice (`batchall.view` in `localStorage`) must not be changed by using the phone layout.
- `python3 -m unittest discover -s tests` and `.venv/bin/python manage.py test hosted` keep passing. The new browser tests skip, not fail, when Chrome is missing.
- Code, comments, commit messages and docs are plain and professional. No `Co-Authored-By` or Claude-Session trailer on any commit.
- Work on branch `mobile-ui`. Never touch `data/`. Use temp directories and the test fixtures only.

## Review Focus

1. **Landscape and small phones:** 360px wide, 430px wide and 844px wide (landscape) show no horizontal scrolling and no clipped controls. (Task 1 checks this at the start and every later task re-runs it.)
2. **Sheets and keyboards:** opening the filter sheet or the actions sheet never traps the user; Escape and the backdrop close it; the on-screen keyboard does not hide the focused input (use `scrollIntoView` for the focused field).
3. **State survives a resize:** rotating or resizing across 640px keeps the filters, selection, scroll position and open detail panel instead of resetting or duplicating handlers.
4. **Selection and bulk edit** still work for cards in phone mode (tick, tick several, change a field, remove with the confirm dialog).
5. **Hosted mode:** the login page and the signed-in page both fit at 390px, and the account control and Sign out remain reachable.

### Task 1: Browser test harness and baseline

**Files:**
- Create: `tests/browser.py`, `tests/test_mobile_layout.py`
- Test: `tests/test_mobile_layout.py`

**Interfaces:**
- Produces in `tests/browser.py`:
  - `chrome_path() -> str | None`: the first of `google-chrome`, `chromium`, `chromium-browser`, `chrome` found on `PATH`, else `None`.
  - `class Browser`: context manager. `Browser(width, height, mobile=True, scale=2)` launches headless Chrome with `--remote-debugging-port=<free port>` and a temp user-data dir, emulates the device (`Emulation.setDeviceMetricsOverride`, touch on), and terminates Chrome on exit. Methods: `open(url)` (navigate and wait for the `load` event plus the page's `#catalog-status` having text), `js(expression) -> value` (`Runtime.evaluate`, `awaitPromise`, `returnByValue`), `click(selector)`, `type_into(selector, text)`, `resize(width, height)`, `screenshot(path, full=False)`, `console_errors() -> list[str]`.
  - `fixture_server() -> (base_url, close)`: starts `server.make_server(port=0, db_path=<temp db>, art_dir=<temp dir>)` in a thread with a database seeded by `tests/support.py` (`seed_catalog`, then at least 12 owned minis across 5 units, a few with notes, factions, companies and materials, so every layout has content).
  - `overflow(browser) -> int`: `documentElement.scrollWidth - documentElement.clientWidth`, so 0 means no sideways scroll.
  - `small_targets(browser, minimum=44) -> list[str]`: selectors, with text, of visible buttons, links, inputs, selects and checkboxes whose bounding box is shorter or narrower than `minimum`, skipping elements inside `.table-wrap` and hidden ones.
- Tests skip with `unittest.skipUnless(chrome_path(), "Chrome is not installed")`.
